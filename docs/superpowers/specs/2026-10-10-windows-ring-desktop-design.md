# Windows 环状桌面美化应用 — 设计文档

- 日期：2026-10-10
- 状态：已确认（待实现）
- 产品名（暂定）：RingDesk（环桌）

## 1. 产品定位

一款 Windows 桌面美化应用：以**同心圆风扇区**的形式，将已安装应用按分类分区悬浮展示在桌面之上，**不遮挡桌面壁纸**。用户可扫描系统应用、自动/手动归类、点击启动、拖拽调整，获得美观且高效的应用启动与组织体验。

## 2. 已确认的关键决策

| 维度 | 决策 |
|---|---|
| 交付形态 | Electron 桌面应用，可打包 Windows 安装包（NSIS） |
| 环状形态 | 同心圆风扇区分区（按角度切分扇形分类区） |
| 应用来源 | 扫描系统已安装应用 + 关键词自动分类 + 手动拖拽调整 |
| 呈现方式 | 透明浮层式（**壁纸完整可见**，不做任何壁纸写入/替换，系统图标默认不隐藏） |

## 3. 总体架构

### 3.1 进程与模块

```
Electron 应用
├── 主进程 (Node, TypeScript)
│   ├── desktop-layer.ts   置底全屏透明窗口 / 非交互区域鼠标穿透 / 环面板显隐与缩放
│   ├── app-scanner.ts     扫描 .lnk（Windows）/ .desktop 与常见可执行目录（开发预览）
│   ├── launcher.ts        启动应用（shell.openPath / cmd start，参数逐字面传递）
│   ├── classifier.ts      按名称关键词 + 类型规则自动归类到分区
│   ├── store.ts           JSON 配置（应用列表、分类、主题、环面板几何），原子写入 + .bak 备份
│   └── ipc.ts             contextBridge 白名单 API，参数校验
├── 预加载 preload.ts
└── 渲染进程（原生 TypeScript + SVG/CSS，无 UI 框架）
    ├── ring-canvas.ts     风扇区/轨道/极坐标布局引擎
    ├── icon-grid.ts       扇区图标排列、拖拽、点击启动
    ├── center-console.ts  中心搜索 + 常用应用快捷区
    └── theme.ts           玻璃拟态主题系统
```

### 3.2 职责边界

- 渲染进程只负责视觉与交互，所有系统能力（扫描、启动、写注册表、持久化）经 IPC 由主进程执行。
- 渲染进程禁用 `nodeIntegration`，仅通过 `contextBridge` 暴露白名单 API，IPC 入参在主进程侧做形状与类型校验。

## 4. 环状 UI 布局（同心圆风扇区分区）

### 4.1 结构（由内向外）

1. **中心控制区**：圆心内圆 = 搜索框 + 常用应用快捷槽（最近使用/手动固定，最多 8 个）。
2. **分类扇区层**：`360° ÷ N` 默认均分（分类可自定义角度）。每分区为彩色扇面（LCH 色系自动分层），环带区显示分类名；扇区图标按**极坐标网格**排列：按"距圆心距离"分层轨道，每轨道沿弧线布点，最多 4 层，每层 6–12 个。
3. **边缘装饰轨**：最外圈细环，静态只读展示时钟 / 日期 / CPU / 内存占用。

### 4.2 视觉语言

- 玻璃拟态（backdrop-blur 毛玻璃）+ 霓虹描边。
- 深色为主、浅色可切换；面板透明度可调；分类配色饱和度可调。
- 默认 6 大分类：工作 / 开发 / 娱乐 / 设计 / 工具 / 系统（可改名、增删）。

### 4.3 壁纸可见性（核心约束）

- 全屏置底**透明**窗口，仅在环状面板区域绘制内容；环外像素 `α=0` 且鼠标穿透，壁纸完整可见。
- 环状面板为居中圆盘结构，默认直径约占屏幕高度 **72%**；支持拖拽缩放/移动。面板本身以半透明玻璃为底（毛玻璃效果），壁纸从面板下方透出；面板之外（屏幕其余全部区域）完全透明且鼠标穿透，壁纸无遮挡。
- 应用**不写入、不替换、不修改任何壁纸文件/设置**。
- 系统桌面图标默认**不隐藏**，照常显示在壁纸上层；「隐藏桌面图标」作为独立选配开关（默认关），通过注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\HideIcons` 实现，始终提供一键还原。
- 提供环面板「显示/隐藏」开关：隐藏时窗口整体透明 + 穿透，桌面恢复纯净壁纸视图。

## 5. 数据流

```
首次启动
 app-scanner 扫描系统应用 ──► classifier 自动归类
        │                        │
        │                        ▼
        └────────────► store.json（appId/名称/图标/目标路径/分类）
                              ▲
 手动调整（拖拽跨分区 / 新建分类 / 改名换色）──┘

每次启动 / 手动重扫
 扫描增删 → diff 合并（保留用户手动分类归属，仅同步新增/移除）
```

### 5.1 扫描范围与解析

- **Windows**：`%ProgramData%\Microsoft\Windows\Start Menu\Programs` 与 `%AppData%\Microsoft\Windows\Start Menu\Programs` 下 `.lnk`；图标优先取 `.lnk` 内嵌图标，回退到目标 exe 图标。
- **解析**：主进程调用 `powershell` 内 `WScript.Shell` 解析 `.lnk` 目标路径；命令以**白名单固定模板**构造，不拼接任意用户输入。
- **开发预览（Linux/mac）**：扫描 `/usr/share/applications`、`~/.local/share/applications` 的 `.desktop` 文件与常见可执行目录。

### 5.2 自动分类规则

内置关键词库（如 `chrome/edge/firefox → 工具`，`vscode/idea/pycharm → 开发`）；未命中归入「未分类」扇区，由用户拖拽整理。规则文件独立于代码，便于扩充。

### 5.3 持久化

`store.json` 存于 `app.getPath('userData')`，含 `schemaVersion`；支持导出/导入配置。

## 6. 系统集成

| 能力 | 实现方式 |
|---|---|
| 置底全屏透明窗口 | 无边框透明窗口 + `setAlwaysOnTop`，非交互区域鼠标穿透（主进程维护区域光栅） |
| 点击启动 | `shell.openPath(target)`；`.lnk` 走 `cmd /c start "" "xxx.lnk"`（argv 逐字面传递） |
| 隐藏系统图标（选配） | 注册表 `HideIcons`；支持一键还原 |
| 显示桌面 | 由系统 `Win+D` 处理，应用不拦截 |
| 开发预览 | Linux/mac 走 `.desktop` 扫描路径，保证当前开发环境可完整预览验证 |

## 7. 交互设计

- **启动**：单击扇区内图标 → 主进程启动目标应用；失败时 toast 提示并给出"在资源管理器中打开"。
- **拖拽归位**：按住图标拖动跨扇区即修改分类归属（悬停扇区高亮）；拖出面板取消。
- **分类管理**：右键分类环带 → 改名 / 换色 / 调整角度 / 删除（应用归「未分类」）；空白处右键 → 新建分类。
- **中心控制**：搜索输入实时过滤（匹配项在对应扇区放大 + 光晕）；常用槽支持固定/取消。
- **外观设置**：深/浅色、透明度、配色饱和度、环直径比例、字体缩放。
- **快捷键**：`Ctrl+Shift+R` 重扫应用；`Alt+Space`（可配置）呼出/隐藏环；`Esc` 关闭搜索。

## 8. 错误处理

- 扫描失败/为空 → 引导"手动添加应用"（文件选择器）+ 重试。
- PowerShell 不可用 → 降级不解析 `.lnk` 目标，直接 `shell.openPath`。
- 注册表写失败 → 仅提示，不阻塞；始终提供恢复按钮。
- 配置损坏 → 自动恢复最近 `.bak`；若无备份则重置为默认配置，不崩溃。

## 9. 测试策略

- **单元测试（Vitest）**：classifier 分类规则、极坐标→笛卡尔排列计算、store diff 合并、IPC 参数校验。
- **集成冒烟（Playwright + Electron）**：启动 → 渲染环 → 拖拽移动分类 → 搜索过滤 → 隐藏环。
- 当前环境执行 Linux 预览模式的完整测试；Windows 专有路径（注册表/`.lnk`）以 mock 断言命令构造正确性，随包交付 Windows 真机回归清单。
